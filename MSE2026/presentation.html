Problem Statement

  • ML models treat elastic modulus as a single scalar target
  • Systems from 0.01 GPa to 10 GPa are pooled together
  • 50% improvement in soft rubber ≠ 50% in rigid epoxy
Core Issue: Identical numerical changes correspond to fundamentally different mechanical behaviors across stiffness regimes.

Why Regime-Aware Analysis?

  • Black-box ML models lose physical interpretability
  • Models learn spurious correlations between unrelated systems
  • Results do not transfer across material classes
Our Approach: Introduce stiffness-aware abstraction before data-driven analysis.

Sources: Scopus, ScienceDirect, Web of Science

Four Stiffness Regimes

Regime Range (GPa) n Behavior
C1 Soft Elastomeric E < 0.1 23 High amplification, unstable
C2 Semi-soft 0.1 ≤ E < 0.5 47 Maximum tunability, chaotic
C3 Intermediate 0.5 ≤ E < 1.0 82 Controlled reinforcement
C4 Rigid E ≥ 1.0 757 Interface-limited, saturation

Graph Construction

  • Nodes = polymer matrices and composites
  • Edges = relative elastic modulus change (ΔE%)
  • Separate graph for each stiffness regime
ΔE(%) = (Ecomposite − Eneat) / Eneat × 100

Centrality Metrics

  • Weighted Degree Centrality
    → Functional importance (total modulus contribution)
  • Betweenness Centrality
    → Bridging role between response patterns
  • Edge-Weight Dispersion
    → Response stability and predictability

Key Findings

1. Elastic modulus must be interpreted regime-wise
2. Soft → Rigid: amplification ↓, stability ↑
3. Surface modification = organizational mechanism
4. Graph representation → explainable extraction

Conclusions

Regime-aware abstraction is necessary before ML
Framework transforms heterogeneous data → structured knowledge
Applicable for knowledge-guided materials design
